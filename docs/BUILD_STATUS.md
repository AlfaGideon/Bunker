# Проверки и подготовка APK

## Добавлено на втором этапе

- `game/scripts/vote_rules.gd`: отдельный подсчёт голосов. Игнорирует голоса за себя, от выбывших и за недопустимых кандидатов; различает отсутствие голосов, победителя и второй тур. Повторная ничья разрешается случайным выбором только среди лидеров.
- `tools/test_rules.gd`: 11 проверок, включая смену голоса, оба вида ничьей и ограничение кандидатов второго тура.
- Визуальная сцена использует этот подсчёт вместо прямого удаления выбранного участника. Голоса остальных по-прежнему задаются тестовой фикстурой, это не онлайн и не боты.
- `export_presets.cfg`: debug Android preset, package ID `org.bunker.prototype`, ARM64 для телефонов и x86_64 для эмулятора. JSON включён явно, поскольку это не импортируемый Godot-ресурс. Интернет-разрешение не требуется локальному прототипу.
- `.github/workflows/godot.yml`: импорт, проверки правил и headless smoke test сцены.
- `.github/workflows/android.yml`: ручная сборка debug APK на GitHub Actions с export templates и Android SDK. Закреплён Godot 4.5.1, сторонние actions закреплены SHA.

## Фактически выполнено

Локально gdparse разобрал все три GDScript-файла без ошибок синтаксиса. Проверены JSON и формат Git diff. **Тесты Godot ещё не выполнялись**, APK не получен, workflows не запускались. Повторная загрузка движка через GitHub API также перенаправляет на заблокированный хост release-assets.githubusercontent.com.

## Как получить проверку и APK

После публикации этой рабочей ветки в GitHub автоматический workflow проверит проект. Ручной workflow Android запускается для этой же ветки (не main):

```sh
gh workflow run android.yml --ref arena/d3ec098c-bunker
```

Ручной workflow должен быть доступен на стороне GitHub; если файл существует только в новой ветке и ещё не зарегистрирован GitHub, запуск через workflow_dispatch может быть недоступен до его появления в default branch. Не выдавать такую ситуацию за успешную сборку.

В случае успешного выполнения артефакт `bunker-debug-apk` содержит `bunker-debug.apk`; загружать его нужно из конкретного успешного run. Ни run ID, ни готового артефакта на этом этапе нет. При сетевых или SDK-ошибках workflow нужно исправить по реальному логу.

Debug APK подписывается временным ключом в runner и предназначен только для проверки. Повторная сборка с новым ключом может потребовать удаления предыдущей установки. Для постоянного распространения нужен отдельно управляемый ключ подписи, не в репозитории.
