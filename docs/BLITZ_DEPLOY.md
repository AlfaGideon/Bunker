# Развёртывание сервера на blitz.cloud

В корне репозитория уже есть Dockerfile для сервера лобби. В blitz.cloud выберите My own code, репозиторий `AlfaGideon/Bunker`, ветку `main` и корневой `Dockerfile`. Порт приложения — 8080 (или значение переменной окружения `PORT`, если платформа его задаёт). Сервер слушает `0.0.0.0`. Команда по умолчанию — `python app.py` внутри контейнера; переопределять её не нужно.

После развёртывания откройте адрес приложения в браузере: главная страница сообщает о работе сервера. По адресу `/healthz` должен вернуться JSON со значениями `status: ok` и `online_turns: true`. В игре укажите адрес `wss://АДРЕС-ПРИЛОЖЕНИЯ/ws` (без `https://` внутри). Проверить работу WebSocket и полной партии нужно на самом хостинге: локальные тесты этого не гарантируют.

Бесплатное приложение засыпает после простоя; согласно документации blitz.cloud запросы программ его не будят. Перед партией откройте адрес приложения в браузере и дождитесь запуска. Комнаты находятся в оперативной памяти и сбрасываются при перезапуске или засыпании.

Если сборка успешна, но запуск не удался, смотрите вкладки Overview и Logs приложения, а также порт в Settings. Лог сборки не содержит обязательно причину ошибки запуска. Не меняйте команду запуска вслепую: в Dockerfile уже задана нужная. Если причина не ясна, сохраните сообщение Overview и последние строки Logs для диагностики.
