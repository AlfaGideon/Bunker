# 0.40 — лобби работает на blitz.cloud

Сервер лобби развёрнут и отвечает: **https://alfagideon.blitz.cloud**. Сборка идёт из ветки `main` по корневому `Dockerfile`, порт 8080, команда запуска не переопределена. Проверка `https://alfagideon.blitz.cloud/healthz` возвращает `{"status": "ok", "service": "bunker-lobby", "gameplay_sync": false, "online_turns": true}`.

## Что изменилось в игре

Адрес лобби по умолчанию больше не указывает на мёртвый контейнер SnapDeploy: в `welcome.gd` стоит `wss://alfagideon.blitz.cloud/ws`, поэтому создание и поиск комнат работают сразу, без набора адреса вручную. Строка состояния больше не называет сервер «временным».

Клиент перестал быть привязан к одному хостингу. `lobby_client.gd` сначала открывает WebSocket; если хостинг отклоняет рукопожатие или восемь секунд ничего не отвечает, тот же протокол продолжается обычными HTTPS-запросами `/transport/open`, `/transport/send`, `/transport/poll` и `/transport/close`. Решение принимается по состоянию соединения, а не по имени хоста, поэтому приглашение с любого сервера — `wss://…/ws` — тоже работает. Адрес HTTP-корня выводится из адреса сокета (`http_root_for`), переход делается один раз, обратно клиент не возвращается.

## Проверки

- **Живой тест на развёрнутом сервере** в GitHub Actions, [run 41255061636](https://github.com/AlfaGideon/Bunker/actions/runs/41255061636): шесть HTTPS-сессий, боты, приглашение со страницей `/invite/…` и запуск партии только ведущим — `PASS`. Отдельный прогон по WebSocket к тому же адресу тоже прошёл: blitz.cloud пропускает WebSocket, так что игра соединяется напрямую, а HTTPS-опрос остаётся запасным путём.
- **Серверные тесты** локально: `python -m unittest discover -s server` — 17 тестов, OK. Дополнительно поднятый на 8099 контейнерный сценарий отдал `/healthz`, корневую страницу и рукопожатие `/ws` с кодом 101.
- **Godot-тесты** в CI, [run 41255061660](https://github.com/AlfaGideon/Bunker/actions/runs/41255061660): зелёные. `tools/test_lobby_ui.gd` теперь проверяет адрес по умолчанию, вывод HTTPS-корня из адреса сокета для своего и приглашённого хоста и то, что клиент стартует именно с WebSocket.
- **Сборки**: [Android debug APK](https://github.com/AlfaGideon/Bunker/actions/runs/41255061644) и [подписанный релиз](https://github.com/AlfaGideon/Bunker/actions/runs/41255061642) — успешно.

## Ограничения

Бесплатное приложение засыпает после простоя, и запросы программ его не будят: перед партией откройте адрес в браузере. Комнаты лежат в памяти одного процесса и исчезают при перезапуске или засыпании. Игровая синхронизация ходов по-прежнему не сделана — лобби, состав и запуск партии работают, но партия после старта остаётся локальной.
