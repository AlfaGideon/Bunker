## Что появилось

В приветственном меню и меню партии — кнопка **«Проверить обновления»**. Она обращается к публичному GitHub API проекта, сверяет номер версии и формат публикации. При появлении более новой стабильной сборки предлагает скачать её. Черновики, prerelease, старые версии, неправильные теги и ссылки на APK с другого адреса не принимаются.

Скачивание выполняется через системный браузер, затем пользователь открывает APK и подтверждает установку в Android. Тихой установки, фоновой загрузки или нативного установщика внутри Godot в этой версии нет. Игра остаётся доступна без сети; проверка запускается только по кнопке.

## Первая установка с постоянным ключом

Сборки до этого подписывались временными ключами CI. При несовпадении сертификатов Android не разрешит обновиться поверх них. В таком случае **один раз** нужно удалить прежнее приложение и установить `bunker-13.apk` из этого Release. Локальный профиль при удалении потеряется.

После перехода на эту подпись следующие версии с тем же ключом и увеличенным version code устанавливаются поверх приложения с сохранением данных. Для обычного обновления приложение удалять не нужно. Фактический переход между двумя такими версиями ещё нужно проверить на телефоне при следующем выпуске.

## Ключи и публикация

Владелец настроил три GitHub Actions Secrets; workflow успешно прочитал их, подписал APK и проверил результат через `apksigner verify`. `aapt` подтвердил package ID `org.bunker.prototype` и version code 13. Публичный Release содержит только APK и SHA256SUMS — приватного ключа и пароля там нет.

Release pipeline не подменяет отсутствующий постоянный ключ случайным. Приватные значения не записываются в `export_presets.cfg` и исходники приложения. Инструкция по сохранению ключа и выпуску следующих версий: [ANDROID_UPDATES.md](ANDROID_UPDATES.md).

## Проверки

Все 14 GDScript-тестов и Python-проверка согласованности версии пройдены в release workflow. В том числе проверены metadata обновлений, отказ от понижения версии и постороннего APK, создание настоящего диалога, заблокированная до проверки кнопка скачивания и закрытие без сети. API `releases/latest` после публикации возвращает именно `android-13` с ожидаемым именем и адресом APK.

Положительные/отрицательные действия, ограниченная камера, выбранный логотип и живой лагерь сохранены. На физическом BL9000 ещё нужны проверка браузерного скачивания, разрешения на установку, иконки и перехода на следующую подписанную версию.

Все четыре job Godot workflow и обычный Android job на том же commit также успешны. Единый набор из 16 JPEG обновлён и полностью декодирован; значения приватных signing secrets не найдены в tracked source.
