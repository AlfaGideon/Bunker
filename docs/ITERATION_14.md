## Приветственный экран без прокрутки

Длинная правая колонка со ScrollContainer удалена. Главный экран — большая карточка «Начать игру» и сетка из шести карточек: персонаж, параметры партии, настройки, обновления, правила и выход. Карточки появляются с небольшим масштабированием и последовательным проявлением; на касание/фокус меняются цвет и обводка. В режиме уменьшенных эффектов анимация появления отключена.

Все карточки помещаются в исходный экран 1280×720 без прокрутки. На широком телефоне интерфейс остаётся у правого края, лагерь и персонаж — слева. Выбранный логотип, живой огонь и лес сохранены.

Имя и внешность редактируются на отдельной странице «Персонаж». Изменения модели и одежды видны у костра сразу; профиль сохраняется по кнопке или при начале игры. Настройки, параметры партии и правила также открываются как отдельные страницы, а не разделы бесконечного списка.

## Заставка подготовки

«Начать игру» открывает `game/loading.tscn`. Там выбранная модель с текущей одеждой бежит слева направо с оригинальной анимацией KayKit `Running_A`. Это не скольжение неподвижной модели и не процедурное махание конечностями.

Модели и основная сцена загружаются через threaded ResourceLoader; прогресс показывает долю действительно загруженных ресурсов, а не выдуманные проценты поиска. Есть короткая переходная анимация, которую можно пропустить кнопкой «Войти сейчас», когда ресурсы готовы. После подготовки автоматически начинается локальная партия. Окончательное создание узлов основного бункера выполняется в главном потоке, поэтому короткая задержка в момент входа на слабом устройстве ещё возможна.

«Вернуться к костру» отменяет вход без создания мира и увеличения счётчика партий; активные запросы ресурсов сначала завершаются, чтобы не накапливать незабранные результаты загрузки. Ошибка подготовки не оставляет пользователя без кнопки возврата. Системная кнопка «Назад» также возвращает к костру.

**Сетевого поиска партий пока нет.** Заставка честно называется «Подготовка партии», внизу приветственного экрана обозначена локальная игра. В режиме уменьшенных эффектов персонаж стоит в idle вместо перемещения по экрану.

## Новое имя, прежняя совместимость обновлений

- Имя в Android: **Бункер — Последний шлюз** вместо «Бункер — прототип».
- Основной файл: `Bunker-Posledniy-Shlyuz-14.apk`.
- Прежний package ID и постоянный сертификат подписи сохранены.
- В Release дополнительно остаётся идентичный `bunker-14.apk`: установленная версия 0.13 проверяет именно такое имя. Удаление этого файла сломало бы её первое обновление.
- Версия 0.14 предпочитает новое фирменное имя при проверке будущих публикаций, но понимает старое.

Перед публикацией workflow скачивает предыдущий подписанный APK, проверяет его через apksigner и сравнивает SHA-256 сертификатов. Изменение имени приложения или APK не должно требовать удаления уже установленной подписанной 0.13.

## Проверки

Тест приветственного экрана проверяет отсутствие ScrollContainer, наличие семи карточек и их размещение по высоте. Сохраняются проверки лагеря, ветра, огня и профиля. Добавлены настоящий переход на заставку, исходная анимация бега, движение слева направо, отмена без создания бункера, повторный запуск после отмены и переход в реальную партию с переносом имени и одежды.

Тест обновлений проверяет старое имя APK и приоритет нового. Постоянный набор скриншотов обновляется под теми же 16 именами; диагностическая заставка не создаёт архивов старых версий. Физический BL9000, быстродействие загрузки и реальное обновление на телефоне ещё требуют проверки.

Все 14 GDScript-тестов, Python-проверка версий, четыре job Godot и оба Android workflow успешны. Release job сравнил SHA-256 сертификатов с опубликованной 0.13 и подтвердил их совпадение. API latest возвращает android-14 с обоими ожидаемыми файлами. Проведён визуальный просмотр настоящих рендеров карточек и бегущего персонажа; все 16 текущих JPEG полностью декодированы, временные JPEG удалены.
