# Сборка экспериментального Unity APK

Workflow `Unity Android prototype APK` собирает только существующий прототип,
не готовую игру. APK имеет отдельный ID `org.bunker.unityprototype`, debug-подпись
и не заменяет установленный Godot APK. Подписанный релиз и сайт обновлений не
изменяются. Артефакт появляется в результатах успешного запуска GitHub Actions.

Для CI требуется Unity ID, подходящий для бесплатной Unity Personal. Установщик
[buildalon/unity-setup](https://github.com/buildalon/unity-setup) загружает редактор
и Android-модули на временный runner, а
[buildalon/activate-unity-license](https://github.com/buildalon/activate-unity-license)
пытается активировать Personal по данным аккаунта и вернуть лицензию после сборки.
Необходимые Actions secrets: `UNITY_USERNAME`, `UNITY_PASSWORD`. Лицензионный
файл вручную переносить не нужно. Эти сторонние actions получают доступ к секретам;
рекомендуется отдельный Unity ID для CI. Не отправляйте учётные данные в чат и не
добавляйте их в файлы проекта. Некоторые настройки безопасности аккаунта могут
помешать автоматической активации; в этом репозитории активация и сборка прошли, но работа приложения на устройстве пока не проверена.
Без секретов workflow выдаёт предупреждение и пропускает сборку — это **не
успешная сборка APK**.

После настройки повторно запустите существующий workflow run для ветки
`arena/574beb82-bunker` или внесите изменение в `unity/BunkerUnity/`:
успешный Android job должен приложить APK к run. `workflow_dispatch` появится
в интерфейсе GitHub, только когда файл workflow будет на ветке по умолчанию.
Первый запуск может обнаружить ошибки импорта или компиляции в настоящем Unity;
проверки .NET с заглушками их не заменяют. Пользоваться им как готовой игрой,
сравнивать графику или производительность с Godot до полноценного переноса нельзя.
